# Bun Migration Plan: Pontual RN (npm -> Bun)

Status: draft for implementation. Scope: `rn/` only. The Flutter client (`app/`),
the Deno server (`server/`), and the data tooling (`tools/`) are out of scope and
remain unchanged. Backend, database, static data bundle, and WebSocket protocol
are not affected.

Source of truth for product/design: root `PLAN.md`, `DECISIONS.md`, `AGENTS.md`,
`RN_RECREATION_PLAN.md`. This plan covers only the package-manager and runtime
migration of the React Native client.

## 0. Goal and non-goals

Goal: make Bun the package manager and script runner for the RN client, for
local development, CI, and EAS builds, while keeping the existing Expo SDK 58 /
React Native 0.88.1 stack and all 40 passing tests green.

Non-goals:

- No Expo SDK or React Native version upgrade.
- No backend, migration, or protocol changes.
- No change to Flutter or Deno tooling.
- No adoption of Bun as the bundler (Metro remains the bundler).

## 1. Current state

- `rn/` uses npm: `package-lock.json` (lockfileVersion 3), `npm ci`, `npx`.
- Bun 1.4.4 is installed locally. Node 26.12.1 is installed locally.
- `rn/AGENTS.md` already says to prefer `bunx` when `bun.lock` is present, but
  no `bun.lock` exists yet.
- `.github/workflows/rn.yml` runs `npm ci` + `npx` commands with a Node setup.
- `rn/scripts/setup-android-build.sh` runs `npm install` + `npx expo prebuild`.
- `rn/scripts/build-apk.sh` runs `npx expo export --platform android`.
- `rn/eas.json` has no `bun` version pin; EAS would infer npm from the lockfile.

## 2. Research findings

1. Expo officially supports Bun as a package manager for both local dev and EAS
   builds. EAS selects the package manager from the lockfile present in the
   repo: `bun.lock` (Bun 1.2+) or `bun.lockb` selects Bun. If both an npm
   lockfile and a Bun lockfile exist, EAS may pick the wrong one or warn.
   Therefore `package-lock.json` must be removed from git before migration.
2. Bun does not run lifecycle scripts (postinstall/preinstall/install) by
   default. Dependencies that need them must be listed in
   `trustedDependencies` in `package.json`. In this project only two
   transitive dependencies have install scripts:
   - `@parcel/watcher` (used by Metro's file watcher)
   - `unrs-resolver` (used by ESLint/Jest resolution)
   Both must be trusted, otherwise native bindings are missing and lint/tests
   or the dev server fail.
3. Node.js (LTS) is still required for `bun create expo` and
   `bun expo prebuild`, which use `npm pack` to fetch templates. Keep Node in
   the toolchain and in `setup-android-build.sh`.
4. Bun can run the existing npm scripts unchanged (`bun run test` executes the
   `jest` binary). Jest and `jest-expo` work under Bun as a runner. Use
   `bunx jest`, not `bun test`, so the `jest-expo` preset and config in
   `package.json` apply.
5. TypeScript (`tsc`), ESLint (`expo lint`), and Expo export all work when
   invoked through `bunx`. No bundler change is required.
6. `expo-doctor` passes with 20/20 checks once only one lockfile remains.
7. Verified locally (trial copy, Bun 1.4.4): `bun install` (20.8s),
   `bunx tsc --noEmit`, `bunx expo lint`, `bun run test` (13 suites, 40
   tests pass), `bunx expo export --platform web`, and
   `bunx expo export --platform android` all succeed after adding
   `trustedDependencies` and removing `package-lock.json`.
8. Pre-existing typecheck issue (not Bun-specific): `src/__tests__/remoteConfig.test.ts`
   uses `global.fetch` / `global.fetch = ...`, but `global` is not declared
   under the project's `types: ["jest"]`. This currently makes
   `tsc --noEmit` fail with 3 errors. Fix by using `globalThis` so the
   migration leaves CI green.

## 4. Trusted dependencies

```json
"trustedDependencies": ["@parcel/watcher", "unrs-resolver"]
```

Rationale: Bun skips lifecycle scripts for security. These two transitive
packages need their install scripts to fetch native bindings. All other
dependencies were scanned and have no install scripts.

## 5. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Stale `package-lock.json` causes EAS/npm to win over Bun. | `git rm package-lock.json` in the same commit that adds `bun.lock`. Run `expo-doctor` to confirm single lockfile. |
| Native binding missing because a trusted dependency was missed. | Run full lint + tests + web/android export after migration; scan `node_modules` for install scripts. |
| EAS image Bun version differs from local. | Pin `"bun": "1.4.4"` in `eas.json` only after confirming EAS supports it; otherwise use default and record the chosen version in `DECISIONS.md`. |
| Node still needed for prebuild/templates. | Keep Node install in `setup-android-build.sh` and document in README. |
| `bun test` bypasses Jest config. | CI and scripts use `bunx jest`, not `bun test`. |
| Regression in Android build. | Run `build-apk.sh` (or at least `expo export --platform android`) before declaring done. |

## 8. Rollback

- Re-add `package-lock.json` from git history, remove `bun.lock`, revert
  `trustedDependencies` and the CI/script/README/AGENTS changes.
- EAS reverts to npm automatically once `package-lock.json` is present and
  `bun.lock` is absent.
- No runtime or app behavior changes are involved, so rollback is purely
  tooling.

## 9. Definition of done

- `bun.lock` committed; `package-lock.json` removed.
- `expo-doctor` 20/20.
- Typecheck, lint, tests, web export, Android export all green under Bun.
- CI workflow green on a PR.
- EAS build uses Bun (verified in build logs).
- ADR recorded in `DECISIONS.md`.
- No em dashes in any changed artifact.
